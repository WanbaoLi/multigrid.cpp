# Official sources consulted

Accessed 2026-11-03. These are concise paraphrases, not copied manuals. Public current HPCKit pages are rolling documentation; installed-version evidence is recorded separately. Several `document/detail` pages timed out on direct fetch; the official site's indexed text or its `doc_center/source` page was available. Absence of a retrieved full page is not evidence of an absent API.

| ID | Official source and scope | Consequence for this project |
|---|---|---|
| H1 | Huawei, [HPCKit introduction](https://www.hikunpeng.com/document/detail/zh/kunpenghpcs/hpckit/devg/KunpengHPCKit_developer_002.html). HPCKit groups KUPL, KML, MPI and other components; it describes C/C++/assembly implementations. | Components and their versions must be identified separately. The documentation is not publication of their complete implementation source. Domain libraries do not automatically provide an equivalent Wilson–Clover solver. |
| H2 | Huawei, [Using setvars.sh](https://www.hikunpeng.com/document/detail/en/kunpenghpcs/hpckit/instg/KunpengHPCKit_install_015.html). Describes compiler/library variants and `--kml_kblas` selection. | Capture the loaded environment and resolved libraries; do not silently mix compiler/OpenMP runtimes or assume environment loaded on login selected compute-node ISA. |
| H3 | Huawei, [HPCKit version history](https://www.hikunpeng.com/document/detail/zh/kunpenghpcs/historyversion/history/hmpi_history.html). Later releases change SONAME/API and add memory/thread facilities. | Installed 25.1.0.SPC001 must be treated as its own ABI. New manual examples require header/symbol checks. |
| K1 | Huawei, [KUPL 25.1.RC1 kupl_parallel_for](https://www.hikunpeng.com/document/detail/zh/hpchistory/hpckit/develop251RC1/KunpengHPCKit_developer_033.html). Describes loop ranges, worker callbacks and splitting policy. | Persistent worker scheduling and workload splitting are reasonable experiments; preserve range semantics and explicit concurrency. |
| K2 | Huawei, [current kupl_parallel_for](https://www.hikunpeng.com/document/detail/en/kunpenghpcs/hpckit/devg/KunpengHPCKit_developer_032.html). Shows an additional description field mask. | This specific newer struct layout differs from the inspected installed header; do not initialize newer fields against 25.1. |
| K3 | Huawei, [KUPL asynchronous copy](https://www.hikunpeng.com/doc_center/source/zh/kunpenghpcs/hpckit/devg/KunpengHPCKit_developer_076.html). Describes SDMA, CPU-copy fallbacks, queue/event synchronization and size limits. | Check actual backend. Model a pipeline only when dependencies permit concurrent useful work; include synchronization and transfer costs. Validate size limits against the installed version. |
| K4 | Huawei, [KUPL asynchronous data copy technical article](https://www.hikunpeng.com/developer/techArticles/20251125-1?envFlag=1). Explains independent copy/compute queues and SDMA-based overlap. | This is an implementation pattern to investigate, not performance evidence on the current allocation. |
| K5 | Huawei, [KUPL matrix programming overview](https://www.hikunpeng.com/doc_center/source/en/kunpenghpcs/hpckit/devg/KunpengHPCKit_developer_104.html). Tensor layouts, matrix multiply/accumulate and layout-copy primitives; requires matrix instruction support. | Treat matrix tiling and packing as opportunities. The document warns that compiler support differs; current examples do not establish GCC 10.3 SME support or installed header availability. |
| K6 | Huawei, [26.0.RC1 kupl_malloc](https://www.hikunpeng.com/document/detail/zh/hpchistory/hpckit/develop260RC1/topic_0000002179819768.html). Adds a memory-kind parameter and distinguishes capacity/bandwidth allocation. | Do not copy this signature into the installed one-argument ABI. HBW rules for this installation come from its header and observed binary. |
| M1 | Huawei, [KML overview](https://www.hikunpeng.com/doc_center/source/en/kunpengboostkithistory/220RC1/accel/kunpengaccel_kml_16_0001.html). BLAS optimization includes vectorization, prefetch and data arrangement; KML targets Kunpeng. | Study layout and data reuse, but measure the actual installed library. Published peak-oriented language is not a small-matrix or full-solver guarantee. |
| M2 | Huawei, [KML GEMV](https://www.hikunpeng.com/doc_center/source/en/kunpenghpcs/hpckit/devg/kunpengaccel_kml_0621.html). Defines complex/real interfaces, matrix order, transpose/conjugation, leading dimension and strides. | A 48-by-48 complex coarse matrix is arithmetically compatible when its storage and normalization are mapped correctly. Compare with independent double arithmetic; include conversion overhead. |
| M3 | Huawei, [KML batch GEMM](https://www.hikunpeng.com/doc_center/source/en/kunpenghpcs/hpckit/devg/kunpengaccel_kml_0677.html). Groups small matrix products and documents real/complex entry points. | A later-version batch facility can inform a future experiment, but inspected 25.1 header and SVE symbols lack it. Same matrix with multiple RHS can instead be an ordinary GEMM candidate when convergence state permits. |
| M4 | Huawei, [BlasSetNumThreads](https://www.hikunpeng.com/doc_center/source/en/kunpenghpcs/hpckit/devg/kunpengaccel_kml_0680.html). Runtime thread count; `BLAS_NUM_THREADS` takes precedence over `OMP_NUM_THREADS`. | Explicitly control BLAS concurrency; OpenBLAS-specific settings alone do not prove KML uses one thread. |
| M5 | Huawei, [BlasSetNumThreadsLocal](https://www.hikunpeng.com/doc_center/source/en/kunpenghpcs/hpckit/devg/kunpengaccel_kml_0681.html). Per-caller thread setting. | If using a parallel BLAS library from existing workers, set/verify the intended local concurrency. Prefer a proven thread-safe library variant. |
| A1 | Arm, [ACLE specification](https://arm-software.github.io/acle/main/acle.html), observed version `aef52c2`. SVE intrinsic mapping, scalable lengths, streaming-mode and ZA interfaces. | Use runtime lane counts and predicates. SME streaming/non-streaming interfaces have different state contracts, and vector-length-dependent values must not cross incompatible boundaries. Check compiler feature macros. |
| G1 | GCC, [GCC 10.3 AArch64 options](https://gcc.gnu.org/onlinedocs/gcc-10.3.0/gcc/AArch64-Options.html). Native targeting and scalable versus fixed SVE width. | `-march=native` reflects the host used for compilation; compile on target compute nodes. Default scalable width is portable across supported lengths; fixed-width builds require runtime compatibility. The site compiler is a vendor 10.3.1 build, so inspect actual macros/assembly as well. |
| L1 | Linux kernel, [arm64 ELF hwcaps](https://docs.kernel.org/arch/arm64/elf_hwcaps.html). User-space capability discovery. | Use `getauxval` flags rather than guessing from model names or attempting fault-based instruction discovery. |
| L2 | Linux kernel, [SVE user-space support](https://docs.kernel.org/arch/arm64/sve.html). Per-thread register state/vector length and SVE capability reporting. | Record `PR_SVE_GET_VL` inside the actual execution environment. A master-thread observation does not prove every independently configured thread has an equal length. |
| L3 | Linux kernel, [SME user-space support](https://docs.kernel.org/arch/arm64/sme.html). Streaming mode, ZA state, separate vector length and optional feature flags. | SME-visible does not mean every precision is supported or every toolchain can generate it; check relevant subfeatures and ABI. |
| L4 | Linux kernel, [cgroup v2 cpuset](https://docs.kernel.org/admin-guide/cgroup-v2.html#cpuset). Granted CPUs/memory nodes can differ from requested resources. | Record effective allowed sets. Allowed memory is a prerequisite, not proof of actual page residence; affinity alone does not bind memory. |

All proposed timing effects in these references are hypotheses until measured on the whole propagation workflow. No full proprietary library source or unavailable platform manual was claimed to have been obtained.

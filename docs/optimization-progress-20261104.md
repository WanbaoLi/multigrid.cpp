## 建层质量：完成两轮后保留默认值

当前传播子大约需要24次外层迭代。因为用户会复用层次，增加建层工作可能
通过减少迭代改善稳态求解；这也可能使粗层系统更难求解。相关原始研究
讨论了这种取舍，但其参数和性能不能直接套到本程序。
[原始论文第6.2节](https://arxiv.org/abs/1303.1377)。

先在node5005上使用相同已验证二进制、同一真实组态及独立标量参考做有界
实验。直接SSH运行没有调度器独占保障；启动前检查当前负载、所属计算
进程和调度队列。该限制会与结果一起保留。

| 建层方案 | 完整12列中位数 | 结果 |
| --- | ---: | --- |
| 默认：2轮，每轮3次更新 | 6.165／6.197秒 | 第一轮前后对照 |
| 1轮，每轮3次更新 | 7.934秒 | 更慢 |
| 4轮，每轮3次更新 | 6.895秒 | 更慢 |
| 默认：2轮，每轮3次更新 | 6.140／6.176秒 | 第二轮前后对照 |
| 3轮，每轮2次更新 | 6.182秒 | 总更新次数不变，更频繁重建粗算子，无收益 |
| 论文形式的更新，2轮，每轮3次 | 6.196秒 | 当前偶奇预条件下无收益 |

两轮对照漂移分别为0.52%和0.59%。每组全部12列通过独立残差和参考解检查。
第一轮减少更新时平均外层迭代从21.42上升至27.58；增加到4轮时也上升至
23.50。第二轮改变刷新频率和更新方法仍未改善完整求解。默认建层继续保留，
这组方向暂时降低优先级。这些结果不证明其他组态或ARM上的全部可能性。

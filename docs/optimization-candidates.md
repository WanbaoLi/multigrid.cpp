# 灵晟优化候选与重试条件

本文件是可写设计经验，参考 skill 保持只读。下列是源码观察和实验建议，均不是已经证明的加速。只有完整 12 列传播子的重复 API 墙时和独立精度门能够决定采用。

## 先补齐完整批量路径的诊断

`batched_cycle.cpp` 已累计 restriction、coarse solve、prolongation、SAP 时间，之前 `batched_solver.cpp` 未输出它们。现在在 `LQCD_VERBOSE=1` 时输出与单列相同的 `native profile R ... coarse ... P ... SAP ...` 格式，并带 `nrhs`、`timing_scope shared_batch`、`aggregation rank0_local_sums`。

这里 `R` 是细格到粗格的限制，`P` 是粗格到细格的插值，`SAP` 是按块进行的局部近似求解；`nrhs` 是本次批量中的源列数。数值为零号进程在一次批量调用内累计的局部墙时，不是全进程最大值。整个批量共享这些时间，不能再乘以列数；SAP 包含细层算子和通信，不能再叠加 halo 时间。普通性能样本关闭 `LQCD_VERBOSE` 和 `LQCD_HALO_PROFILE`，单独的诊断样本再开启它们。

基线应记录完整批量诊断，不能用单列诊断替代。建议另分解粗层为矩阵应用、向量正交化、归约等待、内存分配/清零；SAP 分成全局细算子与局部块求解。粗层 MPI 调用墙时含进程到达不齐，不能全部解释为网络延迟。

## 第一优先：复用已存在的粗层实现

源码 `hierarchy.cpp` 默认 `LQCD_COARSE_FUSED=0`、`LQCD_ARM_COARSE_SVE=0`。前者复用 Schur 工作区，并融合逆对角应用与中间向量构造；后者将粗矩阵转成按输出行向量化的列布局。它们可能减少小型矩阵运算的横向归约、临时分配和并行队伍创建。

先在同一节点依次对照两开关的四种组合；同一组合至少三次稳态完整 12 列，开始和结束各复测基线。候选是在上下文建立时读入，不能假装同一个上下文内改环境就完成切换。向量长度、块数、源列分组和所有物理参数固定。另记第一次调用的延迟打包成本和 setup 时间。

历史 `docs/kupl-hbw-optimization.md` 测过 8 进程、296 核、两个粗层开关开启时的 batch 2/4/12，完整传播子有小幅收益；没有隔离两个开关各自贡献，也不是目前的 16 进程环境。因此当前重测有依据，不能把历史 batch 收益直接记作此次粗层收益。

若粗矩阵计算显著缩短而完整时间持平，要检查粗层同步/正交化份额；后续应减少队伍和归约，而不是继续堆矩阵指令。

## 第二优先：SAP 调度与 ARM 半自旋复用

`batched_sap.cpp` 按聚合块分配线程，然后在每块内顺序处理源列。16 个进程时，每进程 64 块，每种颜色 32 块，却使用 37 个线程；这给多源任务并行留下空间。候选为把同色块与源列共同作为工作单元，复用线程私有 rr/ar/dx 缓冲区。这样会牺牲同块多源的系数缓存复用，因此必须同时测工作分配、缓存行为和完整 12 列时间；尝试静态共同调度，再按证据决定是否使用小粒度动态调度。不要仅凭空闲线程数宣称收益。

`wilson_sve.hpp` 当前先循环两个源自旋、三个输出颜色，再在输入颜色循环里加载同一批邻居自旋和完成投影。x86 路径在输出颜色前保存投影并复用。ARM 候选可在每个输入颜色上只加载、投影一次，同时维护三个输出颜色的实部/虚部，共六个 SVE 累加寄存器。保留输入颜色累加顺序、方向顺序、有效邻居谓词、输出尾部谓词和奇偶半块别名契约。

ACLE 的可伸缩 SVE 类型不能直接放入普通 C++ 数组，不能照搬 AVX512 的三个元素数组。可用显式命名寄存器和编译期颜色 helper，或按官方 ACLE 支持的 tuple 操作实现；先看汇编中的加载数、投影指令、寄存器溢出和栈流量。若第一版失败，应据此改循环顺序、缩短寄存器存活期，再同机复测。编译器可能已消除部分源投影重复，不能直接将源码的三次重复等同于三倍机器指令。

现有 `arm_sve_test`、`arm_sve_plan_test` 覆盖随机局部/全局索引、无邻居、部分范围、尾部、半块别名、超大索引回退。至少覆盖关闭/开启候选、16/32/64 字节向量长度，再进行 MPI 完整求解和独立标量 12 列复核。

## 第三优先：批量粗层与归约

当前 `apply_vcycle_batch()` 对每个源列单独调用 `coarse_solve()`，粗层通信、GCR 和归约仍是逐列执行。`batch_gcr_update()` 也逐列正交化和归约。多个源的细层消息已合并，但不等于粗层或 Krylov 归约已合并，更不等于 block Krylov 算法。

有依据的下一步是保留每列独立收敛状态，把同阶段的粗算子应用、向量归约和 halo 合并；只打包活跃源列，记录源列到缓冲区的固定映射。应先实现同阶段锁步批量并对齐标量结果，再考虑粗矩阵多向量乘法。KML 的单线程小矩阵 GEMV/GEMM 或批量接口只有在调用、布局转换、线程管理成本小于减少的数据搬运时才值得使用。必须以实际安装版本接口和官方资料为准，不能先假定 KML 内部使用了 SME。

主要风险是不同源列提前停止、零源、重启时刻不同，以及 MPI 集合调用顺序不一致造成死锁。保留 1/2/4/12 列、部分尾批次、混合零源和重复上下文测试，尤其是 `test_batch12.py`。粗层近似容差可以变化，但最终完整双精度残差门不能放宽。

## 第四优先：内存与通信重叠

16 进程时间分域使每个进程仅有一个粗格时间平面，粗层没有内部格点用来隐藏边界通信。若诊断确认粗 halo 等待占主导，先考虑在发送/接收期间计算与远端无关的对角及空间方向贡献，再等待后追加时间方向；这比立即推广完整四维分域改动更小。累加方向顺序会影响单精度舍入，应独立验证；若等待主要是进程负载不齐，先修复负载而不是增加异步 API。

历史 KUPL HBW 分配因允许内存节点只有 0–15 失败；若新分配允许 16–31 的纯内存节点，这是重新探测的明确条件变化。使用现有 owned sidecar 分配、SDK verify 和独立页面驻留检查；按 NUMA 域核算容量，不能把整套全局副本强绑到 4 GiB 节点。分配成功不等于实际驻留正确，纯内存 NUMA 也不能未经验证就称为 HBM。若合法分配不可用，记录阻塞，保留 DDR 最佳版本。

## 暂不优先的历史候选

- `LQCD_ARM_SVE_PLANNED`：旧完整求解约 0.6%～1.2% 改善，新 592 核对照也没有稳定收益。只有改变系数布局、源投影复用或分块后使离散加载成为新瓶颈，才有理由重试。
- `LQCD_ARM_SVE_TRANSFER`：旧完整求解基本无收益或略慢；新诊断若插值占比显著升高，再考虑多源共用 basis 的融合，不重复同一个单源 tile 实验。
- 粗层 CGS2/DGKS：历史 x86 中收益不稳定。ARM 网络/批量归约构成不同，若真实 profile 指向归约，可有条件重试；需要报告正交性、迭代变化和独立解误差。
- 无依据地扫描大量 MG 参数不能代替分析。只有当粗迭代数、SAP 局部残差下降或外层迭代数据支持某种工作量分配变化时，才制定有限的参数对照。

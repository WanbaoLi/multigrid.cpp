## 计时口径

- 表内统一采用内部纯solver计时：单列是spin=0/color=0真实单RHS求解，绝非12列除12。
  H20取第二轮12列中的第一列QUDA计时；CPU在同库/同参数下补测两次独立单RHS，取第二次。
- 完整12列取第二轮内部solver计时求和。CPU生产路径使用两列batch，共享时间只计一次，
  因而12列耗时无需等于独立单列的12倍。GPU是12次独立求解。
- H20此前公布的外层pure wall为8.171210 / 2.535279 / 1.615333秒；本表内部
  QUDA计时和为8.167430 / 2.533489 / 1.613695秒。二者属于同一轮记录，差值为循环等开销。
- 9755采用同一个历史16 MPI线程扫描中的第二轮，分别16×8、16×16。128核分布于双路，
  不能解释成只启用一个完整CPU。单列补测复用原库SHA和相同MG参数。
- 此前公平Grid对比中的256核6.565272秒来自另一个native批量驱动的外层wall计时；
  这里使用同一线程扫描的128/256核配对数据，没有用后续更小样本替换第二次成绩。
- 灵晟每38核NUMA保留1核，允许每域37线程，因此304/608核规格实际使用296/592核。
  两组同一独占计算节点cn05132、Donau作业1963656、同一SVE库。
- 各实现使用自身MG配置，不要求MG层级完全相同；保持的是物理算子、源、残差和计时范围。
  x86此线程扫描solve SAP=6/coarse tol=.05/base tol=.003；ARM当前默认SAP=4/coarse tol=.1/base tol=.001。
- setup、读场、stout、输出、布局转换及独立复核不计入。新SVE输出的全部12列已由
  独立scalar C++算子逐列复核通过；具体残差、原始计时、来源文件与SHA256保存在JSON。

# node5005 SIMD 与同步优化（2026-10-23）

0.568 s 不是已知硬件极限。这轮在真实 24³×64、8 MPI × 32 OpenMP 下，AVX512 + packed 系数版单列第二次为 **0.395356 s**，后四次中位数 **0.395655 s**；相对之前 0.568291 s 的单列第二次减少约 **30.4%**。这是已测试配置中的结果，不是全局最优保证。

完整 12 列仍按独立零初值依次求解，不能把单列时间当传播子时间。GCR 融合版额外线程扫描 context 的 12 列第二次达到 **4.895757 s**，但五轮为 **5.713064、4.895757、5.607723、4.874705、5.712295 s**，后四轮中位数 **5.251740 s**。因此已经出现第二次 <5 s 的测量，但尚未稳定满足完整传播子 <5 s。

## 改动

- Wilson/SAP 使用共同 AVX512 masked-gather 核。Clover 在寄存器里累加；half-spin 输入投影复用于三个输出颜色。完整格点和局部块共享同一算术实现。
- owned 系数按 `[aggregate][tile][144 planes][16 lanes]` 打包一次；EO 范围允许从 108/540 等非16对齐位置开始，左右两端均用 mask。外部 PyQUDA 布局不变。
- 全局邻接表另建 int32 路径，避免每16站点载入/缩窄64位索引；完整 float 场超过 INT_MAX 时保持 pointer-width fallback。
- prolongation 让一个16站点 tile 跨24基向量留在寄存器中，减少重复写回。
- GCR、可靠修正和 SAP 复用已分配工作区；每次求解仍从零开始。每 rank 每列 minor faults 从约230761次降到约1次。
- fine interior/boundary 的全部/红/黑工作列表随 hierarchy 构建，调用时复用。coarse 没有内部区域可计算时，等待通信后启动计算，保留诊断回退。
- 外层和粗层 GCR 保持原 MGS 顺序，联合计算 `<q,q>` 和 `<q,r>`，一次 Allreduce；归一化、solution/residual 更新和实际 float residual norm 合并遍历。每列 Allreduce 从481次降到396次。最后的完整 double residual 和独立 scalar 验证均保留。

## 正确性、复现与边界

- node5005 packed及融合构建均通过18/18 CTest，包括serial、MPI2/4、halo阻塞/重叠、fine/coarse EO四组合、线程数修改、奇数块和masked尾部。
- packed核另用ASAN+UBSAN验证两端mask、NaN padding、未激活输出不变，以及EO hopping的parity-disjoint alias。
- 三个验收context的12列均以冻结旧独立scalar executable重算完整残差，最大约3.74852e-9；保持17次累计迭代，API refinement_steps=0。融合路径另做fused=0/1的MPI2和EO四组合回归。
- double算子对PyQUDA导出fixture相对误差约3.99e-16，单列解对PyQUDA约1.49e-7，门为1e-6。没有导入预存解或非零初值；setup约70–80 s，不进入求解成绩。
- 没有重新测GPU，不能把这次CPU实测与旧的“GPU 1.x s”据此宣称精确加速比。GPU比较仍需相同12列、精度、计时边界。

证据：[完整机器可读记录](node5005-simd-optimization.json)。原始目录：`.cache/node5005-simd-20261022/final/`、`.cache/node5005-simd-packed-20261022/`、`.cache/node5005-gcr-fused-20261022/`、`.cache/node5005-ab-20261022/`。各build和原旧基线独立保存，未覆盖。

复现使用对应目录的 `run_acceptance.py all --output-root NEW --build-dir NEW`；driver位于 `.cache/node5005-simd-20261022/`，拒绝覆盖已有结果。完整12列使用 `--twelve-rhs --twelve-repeats 3`，普通单列至少5次。冻结库对照运行 `.cache/node5005-ab-20261022/run_ab.py CASE...`，同样拒绝覆盖case。

预分配wrapper已再次通过serial、MPI2、MPI4回归；原始日志在`.cache/node5005-api-final-20261023/wrapper-ctest.log`，最终12列记录和独立残差在该目录的`gcr-fused-preallocated/`。本轮预分配减少内存复制，但没有测出超出波动的时间收益。

源码仍只有x86生产后端；ARM/神威没有硬件实测。细层和setup仍有复制资产、t-slab分解限制。要逼近GPU完整传播子的1.x s，后续主要方向是多RHS tile同时复用Wilson/SAP/P/R系数和通信、owned storage，以及更少同步；当前`solve_many`仍是顺序求解，尚未实现block Krylov。

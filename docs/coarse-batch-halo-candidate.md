# 默认关闭的粗层多源边界消息合并

基于 `5fe1b5f` 的隔离实验，当前没有性能结论。只读参考为
`skills/kunpeng-lqcd-reference/`；实验实现、测试和本记录不写入参考目录。

当前批量粗层实现已经合并独立源列的归约，但源码仍按列依次调用
`coarse_reduced_rhs`、`coarse_schur` 和 `coarse_reconstruct`。每次粗算子
各自发送两个时间边界。018 的轻量诊断前期每两列粗层边界等待约0.25秒，
约为完整12列的1.5秒；详细 verbose 阶段扰动更大。这些等待包含进程到达
不齐，且各项采用独立进程最大值，不能直接当作网络延迟或可回收收益。
后续新归约路径若已将这部分降到很小，应停止此候选而不继续堆实现。

候选 `LQCD_COARSE_BATCH_HALO=1` 只在既有粗层独立多源归约支持的
EO/MGS/fused-GCR路径上启用。EO指偶奇消元；MGS指修正Gram–Schmidt
正交化；GCR指广义共轭残差求解。每列的解、方向历史、停止、重启和真实
残差刷新保持独立，不形成不同源列之间的Krylov空间。

同阶段活跃源列按既有升序打包为一个下边界消息和一个上边界消息；每次
调用独立完成四个MPI请求，使用40/41标签。发送和接收工作区均与标量
路径分离，发送期间不修改，接收完成前不读。MPI仍仅由主线程调用。
矩阵应用按块在外、源列在内，复用同块系数缓存；每列内部方向和矩阵列
的单精度累加顺序保持原样。单列、全零、非支持模式退回原标量边界路径。

兼容既有粗矩阵SVE布局、融合/未融合Schur构造、普通内部格点重叠、空
内部格点的空间前缀重叠，以及实际线程团队缩成1的情形。SVE是Arm可伸缩
向量指令，在x86上不能验证其实际执行。两面周期邻居为同一进程时仍使用
独立缓冲区和标签。动态开关必须在每次求解前集体验证，非法值或进程不
一致不能进入通信。

实际执行证据采用 verbose JSON：`calls`是确实合并多个活跃源列的MPI
交换次数，`send_bytes`是本进程双面发送字节数，`rhs_slots`是各次交换的
活跃列数之和，`max_width`是最大实际合并宽度。仅开关打开不算执行证据。
现有边界profile同时包含合并交换和剩余单列交换，诊断均不参与性能排名。

先用已有NumPy解析解和独立矩阵应用验证1/2/4/12列、部分尾批、混合零列、
依赖列、不同停止步数和刷新；测试同时覆盖MPI2与MPI4，后者每进程一个
粗时间平面。检查开关关闭、其他算法回退、非均匀线程数、限制粗层线程、
融合/SVE选择、关闭重叠和空间前缀重叠。未实际触发的重启或不同刷新次数
必须记录为未覆盖。共享主仓库、既有canonical性能库和灵晟活动源码不改动。

正确性门通过后由主代理审核，才考虑同组态、同层次、同物理参数的完整
12列配对普通计时及独立标量残差验证。只有局部消息数减少不能晋升最佳。

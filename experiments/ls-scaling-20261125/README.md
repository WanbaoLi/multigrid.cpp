# 灵晟 C32 强弱扩展与 C64 节点估算

## C32 强扩展

固定 `32³×64 cfg_10000`，每节点 8 MPI × 64 线程，使用 1、2、4 个节点。
每 rank 绑定两个 NUMA 域各 32 个物理核。固定 `8×8×8×2` 聚合块、粗层 8 线程和
UCX/RoCE。关闭 HBW 副本，保持跨两个 NUMA 域的配方一致。1、2、4 节点分别对应
本地时间长度 8、4、2。

## C32 弱扩展

固定每节点 `32³×64`，每节点 16 MPI × 32 线程，使用 1、2、4、8、16、32 个节点。
将同一份 LIME 按时间平铺，每个 tile 都复核原始 SciDAC 校验和。保留单列 wall RHS，
在每个 tile 的第一张时间面设置同一个 spin/color 分量。反周期边界作用于全局时间
边界一次。该构造用于扩展测试，和各自生成独立物理组态的采样任务不同。

两组固定 Wilson–Clover 参数，从零初值求解三次，以第二轮纯求解为准。
独立标量复核完整相对残差 `≤1e-8`。弱扩展同时记录迭代次数，因为时间范围和
全局算子条件随节点数变化。

## C64 节点数

另用昆山 F64P14 `cfg_1000` 实测 4 节点，每节点 16 MPI × 32 线程，聚合块
`8×8×8×2`。与先前 2 节点的基准对照时需考虑原先 `8×8×8×4` 聚合块和粗层线程
设置的差异。`64³×128` 有 `32³×64` 的 16 倍格点。16 节点使每节点格点数与
单节点 C32 相等。驻留内存仍受 halo、临时缓冲区、rank 数和 HBW 副本策略影响。

当前 native 沿 t 切分，rank 本地至少 2 层时间。C64 若使用 16 节点，保持这一切分
时可用 4 MPI × 128 线程/节点。要在 16 节点保持 16 MPI × 32 线程/节点，需要
支持空间切分才能给每 rank 分到完整聚合块。

[提交脚本](../../tools/multinode/submit_ls_scaling.sh) 接收运行目录、已推送提交与分支。

依赖前一级的独立复核。结构化结果记录源码、二进制、输入、CPU 绑定和 NUMA 内存信息。

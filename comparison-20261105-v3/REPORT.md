# 全核、同smear输入、相同停止阈值：一次完整12列比较

本轮按用户最终要求，只比较每套程序在每种节点上一次完整12列的纯求解时间，
使用全部可用核。两套求解器的迭代停止参数都为相对残差1e-8（十的负八次方）。
这指各自求解方程的停止条件，不是要求两套解之间相差1e-8。

| 节点与全部可用核 | 我们的MG，秒 | PyQCU，秒 | PyQCU耗时/我们的耗时 |
| --- | ---: | ---: | ---: |
| 登录login04，128核 | 77.302 | 1721.939 | 22.28倍 |
| 计算cn19481，592核 | 14.392 | 353.120 | 24.54倍 |

所有数字都来自实际完成的12列，原点4个源自旋×3个源颜色，每列从零初值开始。
没有单列乘12，没有选取最快重复。单位均为秒。

## 计时范围

主表为原生求解调用的墙时合计，MPI取最慢进程。我们的双列批处理将共享计时
只累计一次；PyQCU累计12列及必要的同列补偿求解。smear、规范场读入、Clover和逆、
多重网格建层、输入准备、外部验算、最终写文件都不计入主表。
原生调用内不可分离的布局转换和工作区管理保留，不能把局部核时间当整个求解。

我们的更窄内部求解计时：登录76.650秒，计算13.928秒；完整PythonAPI分别为78.397、14.466秒。
这些是辅助口径，主表使用上面定义的原生调用时间，保持一致解释。

## 相同物理问题与配置

24×24×24×64格点，质量参数−0.277，Clover系数1.160920226，一次四方向stout，
平滑参数0.125，原点单位点源，时间反周期。共同规范场来自同一份已经保存的
双精度smear结果，规范场字节摘要为
`126d658999367b0ece3801c61cd143542d7db0dddc37ab60e6e668e18faa6834`。
两边只转换数据布局及各自边界编码，没有分别smear。

登录节点4MPI×32线程，共128核；计算节点16MPI×37线程，共592核。
都明确配置每个OpenMP线程的place并按NUMA分配进程。登录节点是共享环境；
计算节点作业2039580为独占分配，节点cn19481。两套程序在同一节点顺序运行。

我们的程序采用现有混合精度多重网格，保留双精度真残差检查；PyQCU采用现有
CPU KUPL后端complex128奇偶预处理BiCGStab（levels=1/restart=0），不是MG路径。
PyQCU使用complex128以可靠达到此次精度；没有新写一个混合精度PyQCU求解器。
原生源码都没有为本次比较修改。两边保留各自现成优化配置，计算节点我们的程序
采用选择性KUPL HBW分配，PyQCU采用普通内存；MPI格点分解也按各自支持方式设置。
因此结论是本问题上两套实际求解配置的性能，不是隔离到单一SIMD内核的比较。

MG的外层迭代包含SAP和粗层求解，BiCGStab每步计算内容不同，迭代次数不能
直接当等量工作相除。达到的残差可以低于请求值，这是求解器自己的停止行为，
没有为了让两个最终残差恰好相等而额外迭代。

## 为什么这次不同于此前4.3秒

此前PyQCU的4.3秒对应未smear输入、complex64及1e-6阈值。本次使用共同smear
结果及1e-8阈值，待求方程和执行配置都变了；不能用4.3秒与这次MG时间相除。
本表给出了实际重新测得的同输入、同请求停止阈值结果。单次测试不表示已经
充分测量长期波动，也不声称PyQCU所有可能后端或参数都已达到全局最快。

## 一次计算的选择与留档

登录节点我们的程序在用户提出“只算一次”之前已完成多轮，主表只取该进程首次
完整12列77.301513609秒，没有取后面的更快样本。PyQCU登录任务原安排两轮，
按用户最新要求在首轮12列及其外部检查全部保存后停止后续重复；原任务停止状态
和第一轮完整样本分别保留在`login-single-accepted.json`及原始日志中。
计算节点的新v3驱动从开始就只执行一次完整12列，随后正常结束。

更早1e-10试算、128核计算节点中途取消的测试和其他重复均原样保留，未混入主表。
附录`summary.json`记录本次四项实际来源和逐列迭代数，`evidence/`保存复现脚本、
输入元数据、计时、残差、停止记录与取消记录。大规范场、传播子数组和平台库留在超算。

计算节点实际命令，依赖同目录的环境和驱动，必须在已分配节点顺序执行。

`prepare.py`复用已保存的smear输入和登录库；`prepare_common.py`及`build_login.sh`
的原始准备过程在v2目录和证据包保留，准备时间未加入主表。
这些站点路径依赖脚本不在x86机器执行；两平台原生源码与工具链路径均有留档。

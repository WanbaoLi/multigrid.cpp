这是正在运行的实验基础设施归档，**没有新增最佳版本或完成声明**。首要指标是
复用层次后的完整 12 列公共 API 墙时。数学实现、原点源、零初值、输入、精度门、

`frozen-helpers/` 保存实际部署文件及其前置版本的原字节，`files-manifest.json`

worker8/2023152/cn19483；每次换分配仍须重新检查实际节点、可用核、运行库和期限。

## 本轮修正的问题

旧的观察器从阶段启动起等待 20 秒，真实输入校验可能已经耗尽窗口。新包装器
在原 `Solver.setup()` 调用前、加载规范场后读取 rank 0 和 rank 8 的实际库映射；
其余进程共同等待取证结束，再调用原建层函数。正式求解计时内没有观察器。

实际 HMPI 启动器会在库搜索路径前添加两次自身库目录。新版本记录原样的实际
路径，以固定的这两项前缀加每个 case 请求的路径来校验；还逐个核对实际加载的
OpenMP、C++、GCC、libc、MPI、求解库及 KUPL 文件摘要。未知额外前缀、重复
OpenMP 库、其他依赖变化、缺少要求的 KUPL 映射仍拒绝验收。旧 c5 运行库审计
函数只转换一处“预期库路径”表达式，其余表达式及全部实验决策方法不变，状态
记录转换前后的语法树摘要。已有 sidecar 不被规范化或改写。

`139d-capture-v5-sdk-worker8` 的真实 16 进程小格点检查已经通过：库映射取证、
原建层调用及进程清理完成。这不代表完整传播子的精度或性能通过。正式任务
`141-phase5-worker8-v5` 正在运行，控制顺序为：

1. 32 线程、37 线程、32 线程，各自独立建层，放置和建层使用每进程 37 核。
2. SDK 默认、SDK PASSIVE/零自旋、旧 GOMP 默认、旧 GOMP PASSIVE/零自旋、SDK 默认。

每个进程先求一次完整 12 列预热，再取三次完整 12 列稳态样本，最后检查全部
12 列独立双精度残差和参考解误差。只有通过两侧控制、至少 3% 收益及原有噪声、
漂移和精度门，才能更新主 campaign 的最佳指针。

`profile_benchmark_publication_v6.py` 已完成本地流程检查，尚未部署或执行。它复用
原 `profile_full12.py` 的 49 Hz、DWARF 4096 字节调用栈记录，只在单独诊断运行的

检查的已保存传播子来自最后一次轻量诊断样本。最终详细调用的传播子不保存，
这个范围在报告中明确记录。profile 不参与普通性能排名，采样占比也不能直接
当作可消除的墙时比例。

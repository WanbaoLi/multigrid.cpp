# 2026-11-05 收口交付：灵晟完整12列传播子

按用户最新要求，以复用建层后一个源点的完整12列求解低于15秒收口，停止新优化。
保留自研多重网格052实现；没有采用两次Clover复用候选，也没有为性能降低精度。

## 最快时间和重复性

这里的“一次”是一个源点的4种源自旋、3种源颜色，共12列，全部零初值。
计时为完整Python求解API墙时，包含布局转换、全部批次、混合精度求解及完整残差检查。
不是单列乘12，不是局部算子，也不是仅C++内部计时。每次最多并行处理2列。
规范场读入、一次stout、建层、写传播子和外部独立验算均另计。

| 灵晟cn19480，165-control-b | 13.487815、13.536358、13.521398 | 13.521398 | 13.487815 |

可对外报告：**灵晟最快单次13.305秒；重复测试中位数13.329～13.521秒**。
灵晟前后对照中位数漂移1.45%，六个稳态样本全部小于15秒；两个独立进程分别建层，
每个先进行一次完整12列预热，再保留三次完整12列样本。
node5005两个进程的中位数漂移0.71%。本问题上灵晟约耗时为9755的2.17～2.20倍。

## 在程序中复用建层

同一组态的多个源点应共用同一个`Solver`对象。下面是现有基准所使用的调用顺序，
变量`solver`表示已创建的求解器，`gauge`表示当前MPI进程拥有的规范场，`point`是
源点的四个全局坐标；`propagator`为12列结果，`stats`为各列收敛记录：

```python
solver.load_gauge(gauge, 'lex')
solver.setup()                      # 同一个组态只做一次
solver.set_threads(32)              # 灵晟；node5005使用12
for point in [(0, 0, 0, 0), (4, 4, 4, 8)]:
    propagator, stats = solver.solve_propagator(point, 1e-8, layout='lex')
    # 保存本源点结果后继续；每个源点的12列都从零开始
```

上述片段放在现有Solver上下文内，仍需采用对应JSON中的环境、建层线程和批大小。
不要为每个源点重新创建Solver或重复setup。不同坐标的独立参考解须匹配该坐标；
片段中的第二个坐标仅说明API用法，不是本报告的性能验收结果。
